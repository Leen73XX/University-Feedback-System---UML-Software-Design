# 🎓 University Feedback & Support System

A Software Engineering Analysis & Design Project that models a centralized university platform for managing student suggestions, feedback, and support requests.

The project focuses on the requirements analysis and system design phases of the Software Development Life Cycle (SDLC), establishing a structured foundation for the system before implementation.

⸻

## 📌 Project Overview

The University Feedback & Support System is designed to improve communication between students and university departments by providing a centralized platform where students can submit and track different types of requests.

### The system supports four main categories:

- 🎓 Academic Support
- 🏥 Health Support
- 🧠 Psychological Support
- 💡 Suggestions

Students can submit requests, track their status, receive notifications, rate the provided support, and access awareness and educational content.

For urgent health or psychological cases, the proposed system also includes an Emergency Support feature that enables live chat or voice communication with responsible staff.

⸻

## 🎯 Project Objectives

The project aims to design a system that:

- Provides a structured channel for student feedback and support requests.
- Automatically routes requests to the appropriate department.
- Allows students to track their submitted requests.
- Keeps students informed through status notifications.
- Enables students to evaluate the quality of received support.
- Provides awareness and educational content.
- Supports real-time communication for urgent cases.
- Maintains the privacy and security of student information.

⸻

## 🔄 Development Methodology

The project follows the Waterfall Model, where the development process progresses through structured sequential phases:

1. Requirements Analysis
2. System Design
3. Implementation
4. Testing
5. Maintenance

For this project, the primary focus was on requirements analysis and system design, defining how the proposed system should behave and interact before moving into implementation.

⸻

## 📋 Requirements Engineering

### Functional Requirements

The proposed system allows students to:

* Create an account using their university email.
* Select a request category.
* Submit support or suggestion requests.
* Track current and previous requests.
* View request details and responses.
* Rate completed support services.
* Access awareness and educational content.
* Use emergency live chat or voice communication when applicable.

The system is also designed to:

* Verify university email addresses.
* Route requests to the appropriate department.
* Store and update request statuses.
* Send notifications when request statuses change.
* Allow staff to process and respond to requests.
* Allow administrators to manage awareness content.

### Non-Functional Requirements

The system design considers:

* Performance: Fast response to user actions.
* Security: Protection of personal and academic information.
* Privacy: Secure handling of student data and communications.
* Compatibility: Accessibility across modern devices and browsers.
* Scalability: Ability to handle multiple transactions efficiently.
